# Memo 5: Project Evolution Aims (Phase 1 - 3 演进目标)

本路线图（Roadmap）定义了 Ideal Mechanics Parser（理想力学解析器）的核心演进阶段。各阶段必须严格解耦，**严禁跨阶段开发与特性越级**。

---

## Phase 1: MVP 与纯等式约束底座 (Foundation & Holonomic Constraints)
**核心目标 (Aim):** 确立"最大坐标法 + 符号推导 + 隐式积分"的绝对核心地位，完成无状态突变的连续动力学解算。

* **图元基石**：实现固定锚点、质点、理想轻杆、光滑轨道、理想弹簧。所有几何约束均表现为绝对的代数等式 $f(x, y) = 0$。
* **万有引力 (The Gravity Update)**：在势能池中原生地支持天体力学，引入 $V_G = -G\frac{m_1 m_2}{r_{safe}}$ 势能项，并加入防崩溃软化因子 $\epsilon$。
* **逃生舱机制 (Expression Injection)**：P1 级核心功能。允许前端注入合法的 SymPy 字符串表达式（如 $F(t) = \sin(\omega t)$），实现非定常约束与受迫振动。
* **投影平面折叠**：支持 `XY`（水平面无重力）与 `XZ`（竖直面重力场，Y 代表竖直坐标）的环境热切换，为后期引入支持力相关的摩擦力做物理降维准备。

---

## Phase 2: 刚体与事件驱动突变 (Rigid Bodies & Event-Driven Mutations)
**核心目标 (Aim):** 攻克时间轴上的"非连续性"数学灾难，引入体积、旋转以及状态突变机制。

* **二维刚体动力学**：节点升级。引入局部坐标系、旋转自由度 $\theta$ 以及转动惯量 $I$，总动能扩充 $T_{rot} = \frac{1}{2}I\dot{\theta}^2$。引入铰接约束 (Hinge Joint)。
* **"事件驱动"双子星 (Event-Driven Architecture)**：
    * **碰撞 (Collisions)**：引入恢复系数 $e$。利用 SciPy `events` 监控碰撞边界，精准打断积分，通过冲量与动量守恒重构速度向量后重启积分。
    * **限制**：P2 **仅支持两两碰撞 (Pairwise Collisions)**。当三个以上物体同时接触时，将碰撞事件按极短时间窗口内的多次独立双体碰撞序列处理，不实现多体同时碰撞求解器。
    * **软绳 (Soft Ropes)**：底层实现采用**"中断-重构-重启"范式**。由于 `solve_ivp` 不能在积分中途增删约束维度，流程如下：
        1. 监控距离阈值事件 $||x_1 - x_2|| - L = 0$（绷紧事件）和 $||x_1 - x_2|| < L$ 且速度分量向外（松弛事件）。
        2. 事件触发 → 销毁当前 `solve_ivp` 进程。
        3. 根据新的拓扑状态（增/删杆约束）重新执行 Step 1~Step 4，生成全新的符号方程组。
        4. 应用冲量与动量守恒计算突变后的速度向量。
        5. 以新状态为初值，重新启动 `solve_ivp`。
    * 注意：重构开销极大，高频振荡场景下可能被频繁打断，前端应设置"最大仿真时长"护栏。
* **带边界的局部坐标系 (Movable Wedge)**：
    * 实现拥有真实物理长度 $W$ 和高度 $H$ 的"有质量斜面"。
    * 引入边界监控，当滑块坐标脱离斜面局部定义域时，触发"约束解除"事件，转换为自由落体。

## Phase 3: 摩擦耗散与反向寻优 (Friction, LCP & Heuristic Optimization)
**核心目标 (Aim):** 挑战计算动力学的深水区，解决非完整约束，并将解析器升格为"题目逆向破解工具"。

* **摩擦力与 LCP 求解器**：
    * 引入动摩擦与静摩擦的切换（符号函数 $\text{sgn}(v)$ 与死区）。
    * **LCP 平行引擎**：拉格朗日乘子法与 LCP 是两种截然不同的数学框架，不存在"逐步过渡"。LCP 作为**独立的平行解算引擎**实现：
        1. 用户在前端勾选"启用高级摩擦/堆叠"模式后，后端直接切入 LCP 分支。
        2. LCP 引擎不经过 SymPy 拉格朗日推导，而是直接构建接触互补条件，使用投影高斯-赛德尔 (Projected Gauss-Seidel, PGS) 迭代求解。
        3. 普通模式（无摩擦/简单问题）仍使用默认的拉格朗日乘子法。两种引擎在 P3 并存，由系统配置路由。
* **黑盒寻优 API (Optimization Interface)**：
    * 利用后端纯数学符号化的优势，将物理引擎封装为黑盒评估函数 (Fitness Function)。
    * 对接遗传算法或多目标优化算法（如 NSGA-III），解决极端的逆向工程问题（例："求解精确的初始速度向量区间，使得多节混沌摆的末端在 $t=5$ 秒时无碰撞穿过特定坐标孔径"）。
