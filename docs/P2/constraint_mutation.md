# 约束突变引擎 (Constraint Mutation Engine)

## 问题

软绳的物理行为两种拓扑状态切换：
- **松弛态**：无约束，质点自由运动
- **绷紧态**：约束激活，杆等式约束 $f_c = 0$ 生效

`solve_ivp` 不能在积分中途增删约束方程维度，因此必须采用"中断-重构-重启"范式。

## 状态图

```
                  ┌─────────────┐
       ←←←←←←←←←←│  松弛态     │
      ↓           │ (无约束)    │
      │           └──────┬──────┘
      │                  │ 距离 = L 且速度向分
      │                  │ 背离方向（绷紧事件）
      │           ┌──────▼──────┐
      └───────────│  绷紧态     │→→→→→→→→→→→
                  │ (杆约束)    │
                  └─────────────┘
                   距离 < L 且
                   速度分量向外（松弛事件）
```

## 实现流程

```
1. 初始拓扑（无杆约束）→ 构建符号方程 → 启动 solve_ivp
2. solve_ivp 监控绷紧事件: ||x₁ - x₂|| - L = 0（由正变负 → 距离达到 L）
3. 事件触发 → 终止 solve_ivp
4. 应用动量冲量跳变（完全非弹性绷紧）:
   Δv 沿杆方向，动量守恒，损失分量动能
5. 重新生成拓扑（插入杆约束）→ 重新执行 Step 1~4 → 重启 solve_ivp
6. solve_ivp 监控松弛事件: ||x₁ - x₂|| < L 且速度背离
7. 事件触发 → 终止 → 移除杆约束 → 重启
```

## 注意事项

- **性能**：每次重构都涉及 SymPy 符号推导 + lambdify 编译，开销极大。高频振荡场景（反复绷紧/松弛）可能使仿真速度下降 100x。
- **前端护栏**：建议在前端设置"最大仿真时长"或"最大突变次数"保护。
- **事件竞争**：当多个软绳同时到达绷紧阈值时，只处理最先触发的事件，其余在下一周期处理（事件队列序列化）。
